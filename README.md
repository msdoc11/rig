## Возможности

- SSR: страница приходит готовым HTML, браузер его «оживляет».
- Реактивность: когда меняется состояние, патчатся только изменившиеся узлы DOM.
- Вложенные компоненты: `<TodoItem :todo="t" @remove="remove(t.id)" />`, `#[Prop]`, слоты, `emit`.
- Компоненты вставляются тегами прямо на страницах: `<TodoList />`.
- Переходы между страницами без перезагрузки; layout и его компоненты сохраняют состояние.
- События с сервера: `$this->broadcast()` доходит до других вкладок и пользователей.
- Ленивые компоненты со скелетонами: медленные выборки не задерживают открытие страницы.
- Спекулятивная загрузка: страница грузится заранее, пока курсор над ссылкой.
- Свои страницы ошибок: `app/errors/404.php`, `app/errors/error.php`.
- Состояние только в браузере (`#[Client]`): вкладки, модалки, фильтры без запросов к серверу.
- Optimistic-обновления: число меняется в момент клика, сервер подтверждает позже.
- HMR: правка шаблона, стиля или PHP-кода компонента применяется без перезагрузки, состояние сохраняется.
- Ошибки шаблона ловятся при компиляции, с номером строки и подсказкой («может быть, «count»?»).

Бэкенд написан внутри фреймворка, сторонних пакетов нет:

- **PostgreSQL** из коробки: `rig dev` сам создаёт и запускает базу проекта. Есть конструктор запросов, модели, миграции и сиды; MySQL и SQLite тоже поддерживаются.
- Сессии, CSRF, вход и роли, middleware страниц и `#[Guard]` на компонентах, `throttle`.
- API-маршруты `app/api/*.php` с валидацией и JSON-ответами.
- Загрузка файлов прямо в компонент: `<input type="file" r-model="photo">`, превью, `->store('avatars')`.
- Очередь задач, почта (SMTP и журнал) и расписание. В разработке их выполняет `rig dev`.
- `.env`, журнал `storage/logs`, кеш данных.

Интерфейс:

- `r-model` на своих компонентах (`#[Model]`), общее состояние `#[Shared('cart')]`.
- Анимации `r-transition`, `debounce` и `throttle` для событий и `r-model`.
- Свой JS там, где он нужен: `r-js="chart"` и модуль `app/js/chart.js`.
- Переводы `t()` в шаблонах и PHP, теги `<head>` и Open Graph для каждой страницы.
- Статический сайт: `rig generate` собирает его в `dist/`.

## Запуск

Для разработки хватает одной команды. От системы нужен только PHP 8.1 или новее.
Composer, Node и отдельный веб-сервер не нужны.

```bash
git clone https://github.com/msdoc11/rig.git
cd rig
php rig/cli.php dev
```

При первом запуске `rig dev` создаёт `.env` из `.env.example`. По умолчанию там своя база PostgreSQL проекта:
`rig dev` создаёт её в `storage/postgres` и запускает сам, если PostgreSQL установлен. Программы PostgreSQL rig ищет в PATH
и в обычных местах установки. Если не найдёт, укажите папку в `.env`: `PG_BIN=/usr/lib/postgresql/16/bin`.

Глобальную команду достаточно установить один раз. После этого `rig` работает в любом терминале и в любом проекте rig
(команда ищет `rig/cli.php` в текущей папке и выше):

```bash
.\rig install          # PowerShell;  в cmd: rig install;  Linux/macOS: ./rig.sh install
```

На Windows обёртка ставится в `%USERPROFILE%\.rig\bin`, а папка добавляется в PATH пользователя, поэтому откройте новое окно
терминала. На Linux и macOS команда ставится в `~/.local/bin/rig`. Удалить её можно командой `rig uninstall`. Без установки команда доступна
только из папки проекта: `.\rig dev` (PowerShell), `rig dev` (cmd), `./rig.sh dev`.

Остановить сервер можно через `Ctrl+C` в этом окне или командой `rig stop` из любого другого. Процесс останавливается вместе с воркерами,
порты освобождаются.

Что делает `rig dev`:
1. проверяет PHP и расширения, создаёт `storage/` и ключ приложения;
2. компилирует все компоненты, поэтому ошибка в шаблоне видна сразу, с файлом и строкой;
3. запускает сервер приложения: несколько воркеров PHP за собственным прокси. Встроенный `php -S` однопоточный,
   и один медленный запрос задерживал бы все остальные. С прокси запросы обрабатываются параллельно;
4. запускает хаб: HMR и события с сервера (`broadcast()`).

| Флаг | Что делает |
|---|---|
| `--port=8000` | порт приложения |
| `--workers=4` | сколько запросов обрабатывать одновременно |
| `--host` | открыть доступ из локальной сети: в рамке появится адрес для телефона или другого ПК |
| `--hub-only` | только хаб, если приложение уже отдаёт ваш nginx с PHP (`public/` как корень сайта) |
| `--open` | открыть браузер |
| `--verbose` | показывать в логе подключения вкладок |

В лог попадает только то, на что стоит посмотреть: `[hmr]` показывает, что обновилось после правки, `[push]` пишет события с сервера,
`[http]` отмечает ответы дольше секунды, `[error]` показывает ответы 5xx.

| Команда | Что делает |
|---|---|
| `rig dev` | разработка |
| `rig stop` | остановить `rig dev`, запущенный в другом окне или в фоне |
| `rig check` | проверить окружение и все компоненты, прогнать тесты |
| `rig build` | подготовка к выкладке: компиляция, таблица размеров, проверка настроек |
| `rig push` | хаб событий для продакшена |
| `rig make:component Counter` | заготовка компонента, можно с подпапкой: `Admin/UserCard` |
| `rig make:page about` | заготовка страницы, можно с параметром: `blog/[slug]` |
| `rig make:model Order` | заготовка модели; с `--migration` заодно миграция таблицы `orders` |
| `rig help` | список команд |

## Компонент

Компонент занимает один файл в `app/components/`. Сверху идёт PHP-класс с логикой (пространство имён `App\Components`),
после `?>` идут блоки `<template>` и `<style>`. В шаблоне нет PHP, потому что он выполняется и на сервере, и в браузере.

```php
<?php

namespace App\Components;

use Rig\Attr\{Action, Client, Computed, Locked};
use Rig\Component;

final class Counter extends Component
{
    #[Locked] public string $label = 'Счётчик';   // из браузера не изменить
    public int $count = 0;                         // серверное состояние
    #[Client] public bool $help = false;           // только в браузере

    #[Computed('count * 2')] public int $double;   // считается и в PHP, и в браузере

    #[Computed]                                    // считает только сервер
    public function parity(): string { return $this->count % 2 ? 'нечётное' : 'чётное'; }

    #[Action(optimistic: 'count = count + 1')]     // браузер применит сразу
    public function increment(): void { $this->count++; }
}
?>

<template>
  <Card :title="label">
    <p>{{ count }} · ×2 = {{ double }} · {{ parity }}</p>
    <button @click="increment">+</button>
    <button @click="help = !help">Подсказка</button>
    <p r-show="help">Текст подсказки</p>
  </Card>
</template>

<!-- необязательно; стили изолированы внутри компонента -->
<style>
  p { color: tomato; }
</style>
```

Блоки после класса можно ставить в любом порядке. Блок `<skeleton>` задаёт заглушку для `#[Lazy]`. Шаблон можно вернуть и строкой
из метода `template()`, так же работают `style()` и `skeleton()`. Если есть и метод, и блок, используется метод.

Метод `mount()`, если он есть у класса, вызывается один раз при первом рендере, например чтобы загрузить данные из БД.
Элемент-обёртка компонента по умолчанию `div`, другой тег задаётся константой: `public const TAG = 'li';`.

## Страницы и layout

`app/pages/todos.php` открывается по адресу `/todos`. Это обычный PHP, компоненты вставляются тегами:

```php
<?php $title = 'Задачи'; ?>
<h1>Задачи</h1>

<TodoList />
<Counter label="Клики" :count="5" />
<Counter :count="<?= $start ?>" />
<Card title="Заголовок">
  Содержимое
  <template #footer>Подвал</template>
</Card>
```

- `label="…"` передаёт строку, `:count="…"` передаёт выражение: числа, `true`/`false`/`null`, `[списки]`, `{объекты}`, JSON.
- `class`, `style`, `id`, `title`, `role`, `aria-*`, `data-*` попадают на элемент-обёртку. Неизвестное свойство даёт ошибку.
- Внутри `<script>`, `<style>`, `<textarea>`, `<pre>` теги не обрабатываются.
- Из PHP-кода компонент вставляется так: `<?= rig('Counter', ['count' => 5]) ?>`.

Layout лежит в `app/layouts/default.php`, другой выбирается в странице: `<?php $layout = 'admin'; ?>`. В layout
`<?= Rig\Page::styles() ?>` ставится в `<head>`, `<?= $content ?>` туда, где выводится страница, а `<?= Rig\Page::scripts() ?>` в конец `<body>`.

## Переходы без перезагрузки

Ссылки на страницы этого же сайта rig.js открывает сам: запрашивает только содержимое страницы
(JSON по заголовку `X-Rig-Nav`) и заменяет его. Layout и его компоненты, например меню, корзина или лента,
сохраняют своё состояние. Работают «Назад» и «Вперёд», якоря, заголовок вкладки,
`aria-current="page"` у ссылок на текущую страницу и полоска загрузки (`html[r-loading]`).

Обычной загрузкой открываются внешние ссылки, ссылки с `target` и `download`, клик с Ctrl/Cmd/Shift, ссылки с атрибутом `r-reload`,
страницы с другим layout и ответы с ошибкой сервера.

### Кеш показанных страниц

Когда пользователь уходит со страницы, rig откладывает её DOM и живые компоненты в кеш.
Возврат на неё ссылкой или кнопкой «Назад» происходит мгновенно, без запроса к серверу и с тем же состоянием:
фильтры, подгруженные «ещё» товары, введённый текст и прокрутка остаются на месте.

- Если с тех пор было действие на сервере или пришёл `broadcast()`, страница всё равно показывается сразу,
  а её компоненты тихо обновляют данные в фоне. Скелетонов при этом нет, старое содержимое видно до ответа.
  Для обновления вызывается метод компонента `revalidate()`, а если его нет, то `mount()`.
  `revalidate()` нужен, когда `mount()` сбросил бы состояние. Например, каталог должен перечитать столько
  страниц, сколько уже показано, а `mount()` загрузил бы только первую.
- Компоненты в кеше продолжают получать события `#[On]`.
- В кеше хранится до 10 страниц, каждая `page_cache` секунд (по умолчанию 600): `['page_cache' => 300]`, `false` выключает кеш.
- Правка файла страницы (HMR) сбрасывает кеш.

### Спекулятивная загрузка

Страница запрашивается заранее, пока пользователь только целится в ссылку, и к клику ответ уже готов.
Режим задаётся в `config.php`:

```php
'speculation' => 'moderate', // 'conservative' | 'moderate' | 'eager' | false
```

| Режим | Когда грузим |
|---|---|
| `conservative` | при нажатии (pointerdown / touchstart) |
| `moderate` (по умолчанию) | курсор задержался на ссылке 200 мс, или нажатие |
| `eager` | ссылка появилась на экране, плюс всё вышеперечисленное |

- `r-prefetch="eager"` на отдельной ссылке загружает её, как только она появилась на экране, при любом режиме.
  Это удобно для меню: `<a href="/products" r-prefetch="eager">`. Не ставьте его на ссылки с тяжёлыми страницами
  без `#[Lazy]`: сервер отрендерит их, даже если пользователь туда не пойдёт.
- Заранее не грузятся ссылки с `?параметрами` и с атрибутом `r-no-prefetch`, а также ничего не грузится в режиме экономии трафика и на 2G.
- Ответ хранится 30 с. Любое действие на сервере, событие от хаба или правка файла сбрасывают кеш.
- Для ссылок с `r-reload` (их rig не перехватывает) на страницу выводятся правила Speculation Rules API,
  и браузер загрузит такие страницы заранее сам.

### ETag и 304

Страницы и их JSON для переходов отдаются с `ETag` и `Cache-Control: private, no-cache`. Браузер каждый раз
спрашивает сервер, но если страница не изменилась, сервер отвечает пустым `304`, а тело берётся из кеша браузера.
Вместо десятков килобайт по сети идут несколько сотен байт заголовков. Рендер детерминирован (подписи, id и
токены одинаковые при тех же данных), поэтому ETag меняется только вместе с содержимым. `private` не даёт
положить персональные страницы в общий кеш (CDN, прокси). Страницы ошибок не кешируются.

### HTTP/2

HTTP/2 включается в nginx: `listen 443 ssl; http2 on;` в блоке `server` (в `deploy/nginx.conf` это уже есть).
Все запросы страницы идут по одному соединению со сжатыми заголовками и не ждут друг друга.
Браузеры используют HTTP/2 только по https.

Почему переходы идут не через WebSocket: время перехода складывается из сетевой задержки и рендера на сервере, и WS их не уменьшает.
HTTP-соединение и так переиспользуется (keep-alive, HTTP/2), а самые частые переходы вообще не ходят в сеть
благодаря кешу страниц и предзагрузке. PHP-FPM WebSocket не держит, а через сокет теряются коды ответа, редиректы,
кеширование и логи nginx. Для событий с сервера есть хаб (SSE).

## Ленивая загрузка и скелетоны

Медленные выборки не должны задерживать открытие страницы. Компонент с `#[Lazy]` приходит со страницей
в виде скелетона, а `mount()` выполняется отдельным запросом сразу после того, как страница показана:

```php
#[Lazy]
final class ProductList extends Component
{
    #[Locked] public array $items = [];

    public function mount(): void
    {
        $this->items = Product::latest(); // долго — но страница уже на экране
    }
}
?>

<template>
  <div r-for="p in items" :key="p.id" class="card">…</div>
</template>

<!-- необязательно: по умолчанию — один серый блок -->
<skeleton>
  <div r-for="i in [1, 2, 3]" :key="i" class="card">
    <div class="r-sk r-sk-block"></div>
    <div class="r-sk r-sk-line" style="width: 60%"></div>
  </div>
</skeleton>
```

- Скелетон пишется тем же синтаксисом шаблона, стили компонента к нему применяются. Готовые классы:
  `r-sk` (мерцающая плашка), `r-sk-line` (строка текста), `r-sk-block` (картинка или карточка).
  Учитываются тёмная тема и `prefers-reduced-motion`.
- Пока компонент грузится, у него стоит `aria-busy="true"`.
- С `#[Lazy(ssr: true)]` при первой загрузке страницы (и для поисковиков) компонент рендерится сразу с данными,
  а лениво грузится только при переходах между страницами.
- Ленивые компоненты на одной странице грузятся параллельно и не ждут друг друга.
- Переход на другую страницу не ждёт ленивую загрузку. Она продолжается в фоне, и при возврате
  страница из кеша уже с данными. Запросы уничтоженных компонентов отменяются.

Для запросов внутри уже загруженного компонента в шаблоне есть `$busy` (идут запросы) и `$pending.имя`
(выполняется действие «имя»). По ним рисуются скелетоны и состояния кнопок:

```html
<li r-for="i in ($pending.more ? [1, 2, 3] : [])" :key="'sk' + i"><div class="r-sk r-sk-block"></div></li>
<button @click="more" :disabled="$busy">{{ $pending.more ? 'Загружаем…' : 'Показать ещё' }}</button>
```

## Ошибки в режиме разработки

Ошибка в PHP или шаблоне показывает страницу разработчика,
а ошибка в действии или после правки открывает окно поверх страницы. В них есть:

- что случилось: заголовок по-русски («Функции countt() не существует») и исходное сообщение;
- как исправить: подсказка по типу ошибки и ближайшее похожее имя («Может быть, `count()`?»);
- где: файл и строка, подсвеченный код вокруг. Если ошибка сработала внутри фреймворка, показана ещё и строка
  вашего кода, откуда её вызвали. В пути вызова код приложения выделен, а фреймворк приглушён;
- кнопка «Открыть в редакторе», которая открывает файл на нужной строке. Редактор запускает сервер разработки
  (`code --goto файл:строка`), поэтому не важно, пускает ли браузер ссылки `vscode://`.
  Редактор задаётся в `'editor'` в `config.php` или переменной `RIG_EDITOR`: `code`, `cursor`, `windsurf`, `phpstorm`, `subl`;
- кнопка «Копировать ошибку»: сообщение, место, код и путь вызова текстом;
- кнопка «Для ИИ-агента» копирует промпт: устройство проекта, ошибка, файл и строка, код с отметкой строки,
  подсказка, путь вызова и задача «найди причину, исправь минимально, объясни». Его можно вставить в Claude, Cursor или Copilot.

Исправьте файл и сохраните, страница обновится сама. На продакшене этих страниц нет, там показываются `app/errors/*.php`.

## Страницы ошибок

`app/errors/404.php`, `app/errors/500.php` (подходит любой код) и общая `app/errors/error.php` устроены как обычные страницы:
в них работают layout, компоненты и переходы без перезагрузки. Доступны `$status` и `$message`. Текст есть только
у ожидаемых ошибок вроде 403 и 404, у 500 там `null`, чтобы не раскрыть подробности.

- На 404 и другие 4xx всегда показывается страница приложения.
- На 5xx в debug показывается страница разработчика (сообщение, файл, кусок кода, стек), а на продакшене страница приложения.
  Подробности пишутся в `error_log`.
- Если упадёт сама страница ошибки, показывается простой текст, и белого экрана не будет.
- Из своего кода ошибка вызывается так: `throw new Rig\HttpError(403, 'Нет доступа');`.

## Вложенные компоненты

```php
final class TodoItem extends Component
{
    public const TAG = 'li';

    #[Prop] public array $todo = [];        // задаёт родитель, внутри — только чтение
}
?>

<template>
  <input type="checkbox" :checked="todo.done" @change="emit('toggle', $event.target.checked)">
  {{ todo.title }}
  <button @click="emit('remove')">×</button>
</template>
```

В шаблоне родителя:

```html
<TodoItem r-for="t in todos" :key="t.id" :todo="t"
          @toggle="t.done = $event; setDone(t.id, $event)"
          @remove="remove(t.id)" />
```

- `:prop="expr"` и `prop="текст"` задают свойства из `#[Prop]`, остальные атрибуты уходят на обёртку.
- `emit('имя', данные)` в шаблоне или `$this->emit('имя', $data)` в действии вызывает `@имя` у родителя, данные приходят в `$event`.
- Слоты: `<slot></slot>`, `<slot name="footer">запасное содержимое</slot>`. Родитель передаёт содержимое тега
  и `<template #footer>…</template>`. Содержимое слота принадлежит родителю, в нём доступны его переменные и действия.
  `$slots.footer` показывает, передан ли слот.
- У каждого вложенного компонента своё состояние и свои действия. Компонент, появившийся в браузере
  (например, новый элемент списка), рисуется сразу. Если у него есть `mount()` или серверные `#[Computed]`, он сам спросит сервер.
- `#[Prop]` приходит из браузера с каждым запросом, поэтому проверяйте его, как любой ввод.

## Виды состояния

| Объявление | Где живёт | Когда обновляется |
|---|---|---|
| `public int $x` | PHP, хранится на странице в подписанном снимке | изменения из `r-model` уходят на сервер вместе со следующим действием |
| `#[Locked]` | PHP | браузер не может прислать значение (id, роли, списки из БД); локально менять можно |
| `#[Prop]` | задаёт родитель | при каждой перерисовке родителя |
| `#[Client]` | только браузер | мгновенно, без запросов |
| `#[Computed('expr')]` | вычисляется | сразу, и на сервере, и в браузере |
| `#[Computed]` на методе | вычисляет PHP | после ответа сервера |

В состоянии допустимы только скаляры и массивы. Объекты (модели, даты) преобразуйте в массив.

`r-model` работает и внутри `r-for` по computed-списку, например `r-for="t in visible"` с `visible = where(todos, 'done', false)`.
Фильтры возвращают те же элементы, что в исходном списке, поэтому изменение `t.done` попадает в `todos` и уходит на сервер
со следующим действием (если `todos` не `#[Locked]`).

## Шаблон

| Синтаксис | Что делает |
|---|---|
| `{{ expr }}` | вывод, всегда экранируется |
| `:attr="expr"` | атрибут; `false`/`null` убирают его, `true` ставит без значения |
| `:class="{active: on}"`, `:class="['a', b]"` | классы, объединяются со статическим `class` |
| `:style="{color: c}"` | стили |
| `@click="save"`, `@click="remove(t.id)"` | вызов действия на сервере |
| `@click="open = !open"` | изменение состояния в браузере |
| `@click="t.done = true; save(t.id)"` | несколько выражений через `;` |
| `@click="emit('close')"` | событие родителю |
| модификаторы `.prevent .stop .self .enter .esc .space .tab .up .down` | `@submit.prevent="add"`, `@keydown.enter="add"` |
| `r-model="title"` | двусторонняя привязка input / textarea / select / checkbox / radio |
| `r-model.live` | отправить на сервер через 0,3 с после ввода |
| `r-model.lazy` / `.number` / `.trim` | по событию change / как число / без пробелов по краям |
| `r-if` / `r-else-if` / `r-else` | условный рендер |
| `r-show="expr"` | скрыть через `display:none` |
| `r-for="t in todos"`, `r-for="(t, i) in todos"` + `:key="t.id"` | цикл |
| `<Name …/>` | вложенный компонент |
| `<slot>`, `<slot name="x">` | место для содержимого от родителя |
| `$errors.title` | ошибка валидации поля |
| `$event` | событие браузера или данные `emit` (только в обработчиках) |
| `autofocus` | фокус на элементе, когда он появляется |

### Выражения

У выражений свой небольшой язык, отдельный от PHP и JS. Одни и те же выражения исполняются на сервере при SSR
и в браузере по одинаковым правилам, и это проверяют тесты.

- литералы `1`, `2.5`, `'текст'`, `true`, `null`, `[1, 2]`, `{a: 1}`
- `a.b`, `a[0]`, `a['key']`; отсутствующее поле даёт `null` без ошибки
- `+ - * / %`, `== != < > <= >=`, `&& || ! ??`, `a ? b : c`
- `+` склеивает строки и списки: `'Привет, ' + name`, `todos + [item]`
- ложные значения: `null`, `false`, `0`, `''`, пустой список
- функции: `len upper lower trim round fixed abs floor ceil min max json join keys values
  includes push without where whereNot pluck sum slice plural string number`
- конвейер: `price | fixed(2)` означает то же, что `fixed(price, 2)`
- `n | plural('задача', 'задачи', 'задач')`

## Действия и события

```php
#[Action(optimistic: "todos = whereNot(todos, 'id', id)")]
public function remove(int $id): void
{
    TodoStore::remove($id);
    $this->todos = TodoStore::all();
    $this->broadcast('todos-changed');          // остальные вкладки и пользователи
}

#[On('todos-changed')]
public function reload(): void
{
    $this->todos = TodoStore::all();
}
```

- Из шаблона можно вызвать только методы с `#[Action]` или `#[On]`.
- Аргументы приводятся к типам параметров, неподходящее значение даёт ошибку 422.
- `optimistic` видит параметры метода по именам. После ответа сервера его значения заменяют optimistic.
- Действия одного компонента выполняются по очереди. Пока идут запросы, у корня компонента есть атрибут `r-busy`.
- `$this->validate(['title' => 'required|min:3|max:80'])` прерывает действие, ошибки уходят в `$errors`.
  Правила: `required`, `nullable`, `min`, `max`, `email`, `int`, `numeric`, `url`, `date`, `in`, `regex`, `unique`, `exists`,
  для файлов `file`, `image`, `mimes`. Своя ошибка добавляется так: `$this->addError('field', 'текст')`.

Кому доставляется событие:

| Вызов | Кто получает |
|---|---|
| `$this->emit('x', $d)` | родитель: `<Child @x="…">` |
| `$this->dispatch('x', $d)` | компоненты с `#[On('x')]` на этой странице |
| `$this->broadcast('x', $d)` | компоненты с `#[On('x')]` на всех остальных открытых страницах (через хаб) |
| `Rig\Push::publish('x', $d)` | то же, что broadcast, из любого PHP-кода: очередь, cron, вебхук |

В имени события можно указать свойство компонента: `#[On('chat.{roomId}')]`. Компонент с `roomId = 5`
подписан на `chat.5`, и `$this->broadcast("chat.{$this->roomId}", $m)` дойдёт только до этой комнаты.
Свойство должно быть `#[Locked]` или `#[Prop]`, а имена с подставленными значениями сервер подписывает ключом приложения,
поэтому подписаться на чужую комнату из браузера нельзя. Если действие поменяет `roomId`, подписка сменится вместе с ним.

## Хаб: HMR и события с сервера

Хаб работает отдельным процессом и держит одно SSE-соединение на вкладку. Сообщения идут, только когда меняются файлы
или сервер делает `broadcast()`, периодических запросов нет.

- `rig dev` запускает приложение и хаб с HMR, это режим разработки.
- `rig push` запускает только события, для продакшена (под systemd, `deploy/rig-push.service`).

PHP передаёт события хабу через `storage/push.log`, настраивать для этого ничего не нужно. Вкладка подписывается
только на события своих `#[On]`. Список подписан ключом приложения, так что чужие события вкладка не получит.
Отправителю его же событие от хаба не приходит.

На продакшене хаб отдают через nginx на том же домене:

```nginx
location /_rig/hub/ {
    proxy_pass http://127.0.0.1:35730/;
    proxy_buffering off;
    proxy_read_timeout 1h;
}
```

В `config.php` для продакшена это уже прописано: `'hub' => '/_rig/hub'`.

### HMR

- изменился компонент: `/_rig/refresh` пересобирает его с текущим состоянием и присылает новый шаблон и стили.
  Значения сохраняются, новые свойства получают значения по умолчанию;
- изменилась страница: она перезапрашивается без перезагрузки;
- изменился layout, `app/lib` или сам фреймворк: страница перезагружается;
- ошибка в шаблоне или PHP: в браузере появляется окно ошибки, оно пропадает после исправления.

## Как это устроено

```
GET /       PHP рендерит HTML + подписанный снимок серверного состояния + скомпилированный шаблон
клик «+»    rig.js сразу применяет optimistic: count = count + 1
            POST /_rig/action { snap, props, updates, action: "increment", args: [] }
PHP         проверяет подпись, восстанавливает компонент, применяет updates, вызывает increment()
            ← { snap, state: {count: 1, parity: "нечётное", $errors: []}, emits, events }
rig.js      сливает ответ с состоянием, пересчитывает computed, патчит изменившиеся узлы
```

Шаблон компилируется один раз в дерево. Кеш лежит в `storage/cache` и сбрасывается, когда меняется файл класса
или свойства вложенных компонентов. Это дерево рендерит и `Rig\Renderer` на сервере, и `rig.js` в браузере.

## Продакшен

На сервере работают обычные nginx и PHP-FPM, а из процессов rig нужен только хаб событий, и то если используется `broadcast()`.

| Что | Файл |
|---|---|
| сайт: nginx + PHP-FPM, HTTP/2, хаб за `/_rig/hub/` | `deploy/nginx.conf` |
| хаб событий под systemd (`rig push`) | `deploy/rig-push.service` |
| выкладка: права на `storage/`, `rig build`, перезагрузка PHP-FPM и хаба | `deploy/deploy.sh` |

Режим задаёт переменная окружения `RIG_ENV=production`: в nginx это `fastcgi_param RIG_ENV production;`,
в systemd `Environment=RIG_ENV=production`. Настройки для обоих режимов лежат в `config.php`.
На продакшене выключен `debug` (нет HMR, `/_rig/refresh` и подробных ошибок), а хаб доступен браузеру
на том же домене по `/_rig/hub`.

Порядок:

```bash
# на сервере, в каталоге проекта
sudo cp deploy/nginx.conf /etc/nginx/sites-available/example.com    # поправьте домен, пути, сокет PHP-FPM
sudo cp deploy/rig-push.service /etc/systemd/system/                # поправьте пути
sudo systemctl enable --now rig-push
sh deploy/deploy.sh                                                 # и после каждой выкладки
```

`rig build` перед выкладкой собирает кеш компонентов заново, чтобы первый посетитель не ждал компиляции.
Если в каком-то шаблоне ошибка или на продакшене включён `debug`, выкладка останавливается.

Что учесть:
- наружу смотрит только `public/`; `storage/` должен быть доступен на запись пользователю PHP-FPM;
- включите OPcache (`opcache.enable=1`, `opcache.validate_timestamps=0`) и перезагружайте PHP-FPM после выкладки;
- хаб читает события из `storage/push.log`, поэтому он работает на той же машине, что и PHP. Для нескольких
  серверов приложения нужна общая очередь (например, Redis), это пока не реализовано;
- если события с сервера не нужны, поставьте `'hub' => false` в `config.php` и не запускайте `rig push`.

## Безопасность

- Снимок состояния подписан HMAC-SHA256 ключом из `storage/app.key`. Ключ создаётся при первом запуске.
- Из браузера нельзя изменить свойства с `#[Locked]` и `#[Prop]` через `updates` или вызвать метод без `#[Action]`/`#[On]`.
- Запрос без снимка создаёт свежий экземпляр компонента, так появляются новые элементы списков. Поэтому `mount()`
  может доверять только `#[Prop]`, а их тоже надо проверять.
- Компоненты загружаются только из `App\Components` и только если они наследуют `Rig\Component`.
- Запросы к `/_rig/action` требуют заголовок `X-Rig: 1`, а обычная форма с другого сайта его не отправит.
  Кроме того, действия проверяют CSRF-токен сессии.
- На продакшене `debug` выключен (`'debug' => !$prod` в `config.php`). Тогда `/_rig/hmr` и `/_rig/refresh` недоступны,
  а ошибки не раскрывают подробностей.

## Структура

```
app/
  components/   компоненты (App\Components\*)
  pages/        страницы: /about открывает pages/about.php; $title и $layout задаются в странице
  errors/       страницы ошибок: 404.php, 500.php, error.php
  layouts/      обёртки страниц
  lib/          прочие классы приложения (App\*)
rig/
  src/          фреймворк
  runtime/rig.js

  tests/        php rig/tests/run.php
deploy/         nginx, systemd и скрипт выкладки для продакшена
```

`views/` и `docs/` (документация сайта). Миграции и сиды лежат в `database/`, переводы в `lang/`.

```bash
php rig/tests/run.php
```

Каждое выражение из `rig/tests/expr.json` вычисляется в PHP и в JS. Сверяются и значение, и то,
