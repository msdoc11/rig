# Переходы и кеш

Ссылки на страницы этого же сайта rig открывает сам: запрашивает только содержимое страницы и заменяет его. Layout и его компоненты остаются со своим состоянием. Работают «Назад» и «Вперёд», якоря, заголовок вкладки, `aria-current="page"` у ссылок на текущую страницу и полоска загрузки `html[r-loading]`.

Обычной загрузкой rig переходит в таких случаях: внешние ссылки, `target`, `download`, клик с Ctrl/Cmd/Shift, атрибут `r-reload`, страница с другим layout, ошибка сервера.

## Кеш показанных страниц

Уходя со страницы, rig откладывает её вместе с живыми компонентами. При возврате страница показывается без запроса к серверу и с тем же состоянием: фильтры, подгруженные товары, введённый текст, прокрутка.

- Если с тех пор было действие на сервере или пришёл `broadcast()`, страница всё равно показывается сразу, а компоненты обновляют данные в фоне через `revalidate()` или `mount()`.
- Компоненты в кеше продолжают получать события `#[On]`.
- Хранится до 10 страниц, каждая `page_cache` секунд (по умолчанию 600). Значение `false` выключает кеш.

## Спекулятивная загрузка

Страница запрашивается заранее, пока пользователь целится в ссылку, поэтому к клику ответ уже готов.

| Режим | Когда грузим |
|---|---|
| `conservative` | при нажатии |
| `moderate` (по умолчанию) | курсор задержался на ссылке 200 мс, или нажатие |
| `eager` | ссылка появилась на экране |

```php
// config.php
'speculation' => 'moderate',
```

`r-prefetch="eager"` на отдельной ссылке загружает её, как только она появилась на экране. Подходит для меню. Не грузятся ссылки с `?параметрами` и `r-no-prefetch`, а также в режиме экономии трафика.

## ETag и 304

Страницы и их JSON для переходов отдаются с `ETag`. Если страница не изменилась, сервер отвечает пустым `304`, а тело берётся из кеша браузера. По сети идут сотни байт вместо десятков килобайт.
