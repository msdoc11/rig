# Ленивая загрузка

Медленные выборки не должны задерживать открытие страницы. Компонент с `#[Lazy]` приходит со страницей в виде скелетона, а `mount()` выполняется отдельным запросом сразу после того, как страница показана.

```php
#[Lazy]
final class ProductList extends Component
{
    #[Locked] public array $items = [];

    public function mount(): void
    {
        $this->items = Product::latest();   // долго — но страница уже на экране
    }
}
?>

<template>
  <div r-for="p in items" :key="p.id" class="card">…</div>
</template>

<skeleton>
  <div r-for="i in [1, 2, 3]" :key="i" class="card">
    <div class="r-sk r-sk-block"></div>
    <div class="r-sk r-sk-line" style="width: 60%"></div>
  </div>
</skeleton>
```

## Скелетон

`<skeleton>` пишется тем же синтаксисом, что и шаблон, и к нему применяются стили компонента из `<style>`. Если блока нет, показывается один серый блок. Готовые классы:

| Класс | Что это |
|---|---|
| `r-sk` | мерцающая плашка |
| `r-sk-line` | строка текста |
| `r-sk-block` | картинка или карточка |

Учитываются тёмная тема и `prefers-reduced-motion`. Пока компонент грузится, у него `aria-busy="true"`.

## Для поисковиков

С `#[Lazy(ssr: true)]` при первой загрузке страницы компонент рендерится сразу с данными, а лениво загружается только при переходах между страницами.

## Уход со страницы во время загрузки

Переход на другую страницу не ждёт ленивую загрузку: она продолжается в фоне, а при возврате страница из кеша показывается уже с данными.

## revalidate()

Когда страница показана из кеша, а данные могли поменяться, компонент обновляется в фоне. По умолчанию вызывается `mount()`; если он сбросил бы состояние, объявите `revalidate()`:

```php
/** Перечитать столько же страниц каталога, сколько уже показано. */
public function revalidate(): void
{
    $items = [];
    for ($p = 1; $p <= $this->page; $p++) {
        [$chunk, $this->hasMore] = Catalog::page($p);
        $items = [...$items, ...$chunk];
    }
    $this->items = $items;
}
```
