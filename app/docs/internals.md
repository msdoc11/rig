# Как это устроено

## Цикл запроса

1. PHP рендерит HTML, кладёт рядом подписанный снимок серверного состояния и скомпилированный шаблон.
2. Пользователь нажимает «+», и rig.js сразу применяет optimistic: `count = count + 1`.
3. Браузер отправляет `POST /_rig/action` со снимком, изменениями полей и именем действия.
4. PHP проверяет подпись, восстанавливает компонент, применяет изменения и выполняет `increment()`.
5. В ответе приходит новое состояние; rig.js сливает его с текущим, пересчитывает computed и патчит только изменившиеся узлы.

```text
клик «+»   rig.js: count = count + 1             (на экране сразу)
           POST /_rig/action { snap, updates, action: "increment" }
PHP        подпись, компонент, increment()
           ← { snap, state: {count: 1, parity: "нечётное"} }
rig.js     состояние, computed, патч узлов
```

## Шаблоны

Шаблон компилируется один раз в дерево (кеш в `storage/cache`, сбрасывается при изменении файла класса или свойств вложенных компонентов). Это дерево рендерят и PHP на сервере, и rig.js в браузере, поэтому браузер «оживляет» HTML с сервера и не рисует его заново.

## Язык выражений

Выражения в шаблонах разбирает PHP-парсер, а исполняют два интерпретатора: на PHP при рендере и на JS в браузере. Правила значений у них одинаковые: сложение строк и чисел, истинность, сравнение, форматирование чисел. Совпадение проверяют тесты:

```bash
php rig/tests/run.php
```

Каждое выражение из `rig/tests/expr.json` вычисляется в PHP и в JS; сверяются и значение, и то, как оно выводится в HTML.
