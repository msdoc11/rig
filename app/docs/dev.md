# Разработка и ошибки

## Команды

| Команда | Что делает |
|---|---|
| `rig dev` | сервер приложения, HMR, события с сервера |
| `rig stop` | остановить `rig dev`, запущенный в другом окне или в фоне |
| `rig check` | проверить окружение и все компоненты, прогнать тесты |
| `rig build` | подготовка к выкладке: компиляция, размеры, проверка настроек |
| `rig push` | хаб событий для продакшена |
| `rig install` / `rig uninstall` | глобальная команда rig |
| `rig make:component Counter` | заготовка компонента, можно с подпапкой: `Admin/UserCard` |
| `rig make:page about` | заготовка страницы, можно с параметром: `blog/[slug]` |
| `rig make:model Order` | заготовка модели; с `--migration` заодно миграция таблицы `orders` |

Генераторы не перезаписывают существующие файлы. Компоненты из подпапок `rig check` и `rig dev` тоже проверяют при компиляции.

При первом запуске `rig dev` создаёт `.env` из `.env.example`, если `.env` ещё нет.

Флаги `rig dev`: `--port=8000`, `--workers=4`, `--host` (доступ из локальной сети), `--hub-only` (приложение отдаёт ваш nginx), `--open`, `--verbose`.

Встроенный `php -S` однопоточный, поэтому `rig dev` запускает несколько воркеров за собственным прокси: медленный запрос не задерживает остальные.

## Лог

В лог попадают только такие записи: `[hmr]` (что обновилось после правки), `[push]` (события с сервера), `[http]` (ответы дольше секунды) и `[error]` (ответы 5xx).

## HMR

- если изменился компонент, он пересобирается с текущим состоянием, значения сохраняются;
- если изменилась страница, она перезапрашивается без перезагрузки;
- если изменился layout, `app/lib` или фреймворк, страница перезагружается;
- при ошибке появляется окно с объяснением, оно пропадает после исправления.

## Страница ошибки

При ошибке в PHP или шаблоне показывается страница разработчика, при ошибке в действии или после правки появляется окно поверх страницы. В них есть:

- заголовок по-русски и исходное сообщение;
- подсказка, как исправить, по типу ошибки и ближайшее похожее имя;
- файл, строка и подсвеченный код вокруг; путь вызова, в котором выделен код приложения;
- «Открыть в редакторе»: файл открывается на нужной строке. Редактор запускает сервер разработки, поэтому не важно, пускает ли браузер ссылки `vscode://`;
- «Копировать ошибку»: сообщение, место, код и путь вызова текстом;
- «Для ИИ-агента»: готовый промпт с устройством проекта, ошибкой, кодом с отметкой строки, подсказкой и задачей «найди причину, исправь минимально, объясни».

Редактор задаётся ключом `'editor'` в `config.php` или переменной `RIG_EDITOR`: `code`, `cursor`, `windsurf`, `phpstorm`, `subl`.
