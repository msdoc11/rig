# Введение

rig это PHP-фреймворк, в котором интерфейс сразу реагирует на действия пользователя, а JavaScript писать не нужно. Компонент занимает один файл: в PHP-классе описаны состояние, действия и вычисления, ниже идут шаблон (обычный HTML с выражениями) и стили. Браузерную часть фреймворк берёт на себя.

```php
final class Counter extends Component
{
    public int $count = 0;

    #[Computed('count * 2')]
    public int $double;

    #[Action(optimistic: 'count = count + 1')]
    public function increment(): void
    {
        $this->count++;
    }
}
?>

<template>
  <p>{{ count }} × 2 = {{ double }}</p>
  <button @click="increment">+</button>
</template>
```

Нажатие на кнопку меняет число сразу, ещё до ответа сервера. Затем PHP выполняет `increment()`, и браузер обновляет только изменившийся текст. Страница не перезагружается, а в коде приложения нет JS.

## Что внутри

- При изменении состояния обновляются только затронутые узлы страницы.
- Состояние может жить на сервере, только в браузере или вычисляться. Это задаётся одним атрибутом.
- Компоненты вкладываются друг в друга, принимают свойства и слоты, отправляют события родителю.
- Страницы открываются без перезагрузки: уже показанные берутся из кеша, следующие загружаются заранее.
- Тяжёлые данные можно загружать лениво: они приходят, когда страница уже на экране, а до этого на их месте виден скелетон.
- `broadcast()` отправляет события с сервера и обновляет другие вкладки и других пользователей.
- HMR применяет правку без перезагрузки, а сообщение об ошибке показывает, что и где пошло не так.

## Почему без JS

Шаблоны пишутся на небольшом языке выражений, отдельном от PHP и JS. Одни и те же выражения исполняют PHP при рендере на сервере и рантайм rig в браузере. Правила у них одинаковые, это проверяют тесты. Поэтому то, что можно посчитать без сервера, считается сразу в браузере, а то, что требует данных, выполняется в PHP.
