# События и хаб

Компоненты общаются событиями. Событие получает метод с `#[On('имя')]`:

```php
#[On('todos-changed')]
public function reload(): void
{
    $this->todos = TodoStore::all();
}
```

| Вызов | Кто получает |
|---|---|
| `$this->emit('x', $d)` | родитель: `<Child @x="…">` |
| `$this->dispatch('x', $d)` | компоненты с `#[On('x')]` на этой странице |
| `$this->broadcast('x', $d)` | компоненты с `#[On('x')]` на всех остальных открытых страницах |
| `Rig\Push::publish('x', $d)` | то же, что broadcast, из любого PHP-кода: очередь, cron, вебхук |

```php
#[Action]
public function add(): void
{
    TodoStore::add($this->title);
    $this->todos = TodoStore::all();
    $this->broadcast('todos-changed');   // другие вкладки и пользователи
}
```

Отправитель своё же событие от хаба не получает. Для этой страницы есть `dispatch()`.

## Параметры в имени события

В имени события можно указать свойство компонента в фигурных скобках. Тогда каждый компонент подписан на своё событие:

```php
final class ChatRoom extends Component
{
    #[Locked] public int $roomId = 0;

    #[On('chat.{roomId}')]
    public function message(array $m): void
    {
        $this->messages[] = $m;
    }

    #[Action]
    public function send(string $text): void
    {
        $m = Message::create(['room_id' => $this->roomId, 'text' => $text])->toArray();
        $this->messages[] = $m;
        $this->broadcast("chat.{$this->roomId}", $m);
    }
}
```

Комната 5 подписана на `chat.5` и не получает сообщения комнаты 6. Если действие поменяет `roomId`, подписка в хабе сменится вместе с ним.

- В скобках пишется имя свойства или путь по массиву: `{roomId}`, `{room.id}`.
- Свойство должно быть `#[Locked]` или `#[Prop]`, иначе компиляция остановится с ошибкой. Значение обычного свойства браузер может прислать сам и подписаться на чужую комнату. `#[Prop]` тоже приходит из браузера, поэтому проверяйте права на комнату в `mount()`.
- Имена с подставленными значениями сервер подписывает ключом приложения, и хаб принимает только их.
- Если значение пустое (`null`, `''`) или не число и не строка, подписки нет.
- `dispatch()` на этой же странице работает так же: `$this->dispatch("chat.{$id}")` получат компоненты, у которых `roomId` равен `$id`.

## Хаб

Хаб работает отдельным процессом и держит одно SSE-соединение на вкладку. Сообщения идут, только когда меняются файлы (HMR) или сервер делает `broadcast()`, периодических запросов нет.

- `rig dev`: приложение и хаб с HMR, для разработки.
- `rig push`: только события, для продакшена.

PHP передаёт события хабу через `storage/push.log`, поэтому настраивать ничего не нужно. Вкладка подписывается только на события своих `#[On]`: список подписан ключом приложения, чужие события она не получит.

> Хаб читает события из файла, поэтому работает на той же машине, что и PHP. Для нескольких серверов приложения очередь нужно заменить общей, например Redis.
